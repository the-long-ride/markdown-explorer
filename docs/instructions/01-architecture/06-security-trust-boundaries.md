# Security and Trust Boundaries

## Threat surfaces

| Surface | Required control |
|---|---|
| Markdown links | Block dangerous schemes; confirm or route validated external URLs |
| Relative resources | Resolve inside active workspace; reject escape attempts |
| HTML preview | Sandbox; deny same-origin; block active remote networking |
| Local HTML assets | Inline only validated workspace resources |
| Export resource graph | Canonicalize workspace-relative paths, reject escapes, bound reads, and deduplicate referenced assets |
| Export save | Renderer supplies generated bytes and a suggested filename; host/runtime chooses final destination, not a renderer-controlled absolute path |
| Exported runtime JS | Local/offline only; include feature bundles actually required by exported documents; no CDN dependency |
| OS shell actions | Accept exact launch/shell modes and validate paths before opening a workspace or file |
| Converted documents | Treat output as preview content, not trusted executable HTML |
| Updates | Available only where packaged runtime supports trusted installation |
| Tauri local files | Enforce workspace containment and bounded reads |

## HTML sandbox baseline

- `sandbox="allow-scripts allow-forms"`; no `allow-same-origin`.
- `referrerpolicy="no-referrer"`.
- CSP defaults to deny; connections, frames, workers, objects, base URLs, and form targets are denied.
- `fetch`, XHR, WebSocket, EventSource, and `sendBeacon` are blocked in local-first preview.
- Authored JavaScript may execute only inside that isolated preview sandbox. It is not promoted into the exported page's main execution context.
- Passive media may remain remote in ordinary preview behavior, but exported artifacts do not depend on remote runtime scripts or styles.

## Export filesystem baseline

Automatic referenced resources use the host-approved workspace resource bridge. Hosts canonicalize each requested path against the active workspace root and reject traversal/symlink escape outcomes according to the runtime's containment rules. Enumeration is not part of the bridge; exported code cannot browse the filesystem.

Automatic referenced assets are best-effort: a missing reference is recorded as a warning so one broken image does not destroy an otherwise valid document export.

Generated HTML/site runtime files live under reserved package roots and are local to the artifact. Static Website output shares only the union of feature bundles required by exported documents. Standalone HTML embeds its required runtime so it can open offline.

## Export save baseline

`saveExportFile` carries bytes plus a filename/mime-type suggestion. Electron, Tauri, VS Code, and Chromium apply their own save/download capability. PDF generation therefore does not require a privileged Electron `printToPDF` protocol, and there is no renderer-provided absolute output directory or PDF footer template.

## External-open baseline

Desktop shell launches use typed intent. Plain file/folder launches keep their existing semantics. `file-with-parent-workspace` is accepted only for a supported Markdown file and derives the workspace from that file's immediate parent folder; the UI then routes through normal `activateWorkspace` validation and workspace-operation metadata.
