# Web App & Website Runtime Architecture (Chromium Extension Retired)

## Purpose and boundaries

Defines the browser-hosted Web App runtime (`appRuntime: 'web'`) and Interactive Feature Demo Studio (`app/features/`) in `website-app/`, along with the static marketing/landing website and `/features/` studio wrapper in `website/`. As of v1.7.2, the Manifest V3 Chromium extension (`chromium-xtension/` and `ui/src/platform/chrome.ts`) has been retired and removed from the repository; all shared browser-host modules (File System Access scanner, IndexedDB workspace/font stores, search index, media resolver, insights, and Git history stub) were extracted directly into `website-app/src/`.

- **In scope**: `website-app/**` (`vite.config.ts`, `index.html`, `features/index.html`, `src/` including `src/features/*`), `ui/src/platform/web.ts`, `ui/src/utils/webDemoDownload.ts`, `website/**` (HTML/JS/CSS/sitemap assets including `website/features/index.html`).
- **Out of scope**: Shared React UI (`architecture.ui-state-and-runtimes`), desktop/VS Code hosts, and Pages deployment CI (`workflow.build-and-verification`).

## Observable behavior

- **Retired Chromium Extension**: `chromium-xtension/` and `ui/src/platform/chrome.ts` are removed. Release download matching in `website/site-download-helpers.js` no longer includes a `chromium` platform target.
- **Web App (`website-app/`)**:
  - Attaches `window.__webBus` (`EventTarget`) and reports `appRuntime: 'web'` with `appVersion` from `website-app/package.json` (without a `(demo)` suffix).
  - Supports two modes via `?mode=` (`detectMode()`): default `'web'` mode and `'test'` mode (`?mode=test`, loading `manual-tests/*.{md,mdx}`). `main-web.tsx` (`getWebAppTitle(mode)`) sets `document.title` to `'Markdown Explorer – View & Edit'` in `'web'` mode (matching `website-app/index.html`) or `'Markdown Explorer – Demo'` in `'test'` mode before calling `initWebHost(mode)`.
  - Both `website-app/index.html` and `website-app/features/index.html` execute an inline pre-paint theme-sync script reading `localStorage` (`markdown-explorer-ui-state` or `markdown-explorer-web-state`) to apply `dataset.theme` (`'light' | 'dark' | 'auto'`), normalize legacy theme styles (`pet-shiba-memes` -> `tokyo-night`, `night-city-2077` -> `cyberpunk`, `pet-shiba` -> `pet-white-shiba`) onto `dataset.themeStyle` (defaulting to `'raw-grid'`), apply active custom theme metadata (`dataset.customThemeId`) and custom hex CSS variables (`--bg`, `--bg-s`, `--tx`, `--tx2`, `--bd-s`, `--accent`), and render the `.splash` screen and spinner with theme-aware CSS tokens (including the `48px` grid backdrop for `raw-grid`) before React mounts.
  - In `'web'` mode, auto-loads the most recent `localStorage` User Virtual Workspace (or creates one seeded with `Welcome.md` containing `DEFAULT_WELCOME_CONTENT`, which documents closing the workspace to reach Workspace Selection, dragging and dropping `.md`/supported documents/local folders anywhere into the app, and enabling the Chromium `chrome://flags` / `brave://flags` / `edge://flags` **File System Access API** flag) on `ready` unless `explicitlyClosedWorkspace` is true; `loadVirtualWorkspaceHandler` forwards `documentConversionEnabled: Boolean(state.documentConversionEnabled)` in `readyAck`. Also supports local File System Access API folders/single files, drag-and-drop virtual workspaces, permanent entry CRUD, client-side conversion (`web-document-converter.ts`), browser font loading (`browser-font-host.ts` / `browser-font-service.ts`), `blob:` media resolution, and polling/virtual Insights (`web-insights-host.ts` + `browser-insights-host.ts`, with `checkExternalLinks` returning `unsupported`).
  - `web-navigation.ts` (`resolveWebNavigationTarget`, `executeWebNavigation`) resolves relative/root-relative document links against `flatList` (exact then case-insensitive), returning to the Welcome page on empty paths or emitting `navNotFound` for missing/external targets.
  - `webDemoDownload.ts` (`resolveFileContent`, `downloadWebDemoFile`, `downloadWebDemoFolderZip`, `downloadWebDemoWorkspaceZip`, `shouldShowWorkspaceZipButton`) resolves file contents across active `documentSessions`, `sourceDocumentText`, `contentTabs`, `localStorage` virtual workspace maps, the synchronized `DEFAULT_WELCOME_MARKDOWN` fallback for `Welcome.md`, and `window.__webBus` (`loadSearchPreview` -> `searchPreviewResult`) to trigger single-file or ZIP downloads (`createZipBlob`), hides the workspace ZIP button when the workspace contains only `Welcome.md`, and invokes `triggerSupportModalAndResetCounters()` after folder/workspace ZIP exports.
  - **Git History disabled**: `browser-git-history-host.ts` intercepts all 6 Git history commands (`listDocumentHistory`, `readGitRevision`, `compareGitRevisions`, `listRepositoryHistory`, `listRevisionFiles`, `readRevisionFile`) and returns `ok: false, reason: 'unsupported-runtime'`.
- **Interactive Feature Demo Studio (`website-app/features/` & `website/features/`)**:
  - `website-app/vite.config.ts` builds both `main` (`index.html`) and `features` (`features/index.html`) entries under `/markdown-explorer/app/`.
  - `website/features/index.html` serves `/markdown-explorer/features/` in a Raw Grid shell and mounts a full-viewport `<iframe id="features-studio-iframe" src="../app/features/">` forwarding `?feature=` / `#hash` and `hashchange` `mde-demo-select` `postMessage` events.
  - `FeaturesStudioApp.tsx` wraps stages in `PlatformProvider` (in-memory isolated state over `createWebBridge()`), `AppStateProvider`, `HistoryProvider`, `RepositorySnapshotFromHistoryProvider`, and `WorkspaceNavigationProvider` backed by `installDemoBusHost` (`demoBusHost.ts`) without mutating real IndexedDB or `localStorage` workspaces.
  - Supports standalone mode (studio header with `logo-128.png` app icon, `CustomSelect` theme picker matched to app theme tokens, dark/light toggle, video placeholder link, and `[data-testid="feature-demo-sidebar"]` grouping all 11 `FEATURE_DEMO_CATALOG` stages across 6 `FEATURE_DEMO_CATEGORIES`: Workspace, Reader & Data, Authoring, Audit & Git, Productivity, Personalization) and `?embed=1` compact iframe mode.
  - `FeatureStageRouter.tsx` delegates across specialized stage modules (`WorkspaceAndNavStage.tsx`, `AuthoringStage.tsx`, `InsightsAndDiffStage.tsx`, `SearchExportStage.tsx`, `ThemesAndSettingsStage.tsx`) mounting real `ui/src/` components: `WorkspaceSelection`, `WelcomePage`, `Sidebar`, `TableOfContents`, `ScopeViewModal`, `Content`, `MediaModal`, `HtmlDocumentView`, `HtmlPreviewModal`, `MarkdownEditingHeaderActions`, `SplitContent`, `WorkspaceInsightsPanel` (all 6 views via `createDemoInsightsSession`), `DocumentDiffView` (with Source, Split, and Rendered Diff modes), `FileHistoryModal`, `RepositoryHistoryPanel`, `SearchOverlay`, `BookmarksPanel`, `ExportCenterModal`, `DesktopTabBar`, `SettingsModal`, `ThemeRemixModal`, and `TourGuideOverlay`, backed by `demoGitFixtures.ts`, `docs/math-latex.md` (KaTeX equations), `DEMO_RECENT_WORKSPACES`, and a playable HTML5 canvas platformer in `DEMO_HTML_PREVIEW` (`demoHtmlSandboxFixture.ts`, re-exported by `demoMarkdownFixtures.ts`).
- **Local Vite Dev/Preview Mirror (`website-app/vite.config.ts`)**: `serveWebsiteLandingPlugin()` mounts `createWebsiteLandingMiddleware()` to serve `website/` at `/markdown-explorer/` alongside the Vite app at `/markdown-explorer/app/`, redirecting `/` and `/markdown-explorer` to `/markdown-explorer/` and logging local URLs for Entry, `landing.html`, `?mode=web`, and `?mode=test`.
- **Marketing & Landing Website (`website/`)**:
  - `website/index.html` is a redirect-only root entrypoint forwarding `/` (including legacy `?mode=file` -> `web`) straight to `app/?mode=web` and routing section hashes (`#features`, `#gallery`, `#video-demo`, `#download`, `#faq`) to `landing.html${hash}`, with no `?landing=1` HTML page.
  - `website/landing.html` (alongside `privacy.html`, `terms.html`, and `features/index.html`) is the sole marketing landing page using the Raw Grid theme (`data-theme="dark" data-theme-style="raw-grid"`, styled via `landing-raw-grid.css`).
  - `landing.html` replaces the static hero and 4 spotlight `<img>` previews with live interactive `<iframe src="app/features/?embed=1&feature=...">` embeds (`#hero-demo-iframe` switched by `[data-hero-mode]` and 4 `[data-spotlight-iframe]` panels synced with `[data-spotlight-tab]` via `site-effects.js` `mde-demo-select` `postMessage`, using `search-bookmarks` for the Search & Export tab and a full-width stacked layout in `landing-spotlight.css` with the embed above the copy), links to `features/`, and includes the `#video-demo` YouTube walkthrough embed placeholder (`[data-youtube-placeholder]`, `[data-youtube-placeholder-trigger]`, without fake chapter timestamps).
  - Retains prioritized Rust Tauri download buttons including `#dl-win-light-portable-btn` (`tauri-windows-portable` matcher in `site-download-helpers.js`), icon-only GitHub star nav link (`.nav-github-link` + `[data-github-stars]`), `--accent` author link (`@the-long-ride`), View Transition / `is-theme-switching` dark-light toggle animations (`script.js` + `site-foundation.css`), retro-styled footer/legal panels (`privacy.html`, `terms.html`) with 9-language localization (`i18n.js`, `i18n/*.js`, plus `data-i18n-html` support in `script.js`), and `/markdown-explorer/landing.html` + `/markdown-explorer/features/` in `website/sitemap.xml`.

## Workflow

1. `website-app/index.html` (or `website-app/features/index.html`) synchronizes saved theme tokens and renders the theme-aware boot `.splash` screen before module scripts execute.
2. `website-app/src/main-web.tsx` detects mode (`'web'` or `'test'`), sets `document.title` via `getWebAppTitle(mode)`, and calls `initWebHost()`, which initializes `window.__webBus` before dynamically importing `ui/src/main.tsx`.
3. `ui/src/platform/web.ts` (`createWebBridge()`) binds `webview-message` / `host-message` events on `window.__webBus` and persists UI state in `localStorage` (`WEB_APP_STATE_STORAGE_KEY`).
4. UI posts `ready` -> `web-host.ts` initializes the virtual, persisted, or test workspace (or sends empty `readyAck` if `explicitlyClosedWorkspace` is set) and streams `workspaceFilesChanged`.
5. `workspace-operation-state.ts` tags host messages with operation metadata so stale async scans do not overwrite newer workspace/tab transitions.
6. In the Feature Demo Studio (`website-app/features/index.html` -> `src/features-main.tsx`), `FeaturesStudioApp` installs `demoBusHost` over an isolated memory `PlatformBridge`, resolves `?feature=` / `#hash` aliases via `resolveFeatureSlug()`, and updates the active stage on sidebar clicks or parent `mde-demo-select` messages.

## Interfaces and data

- Event bus: `window.__webBus` (`EventTarget`) carrying `webview-message` and `host-message` `CustomEvent`s (and `window.postMessage` `{ type: 'mde-demo-select', feature }` for iframe embeds).
- IndexedDB stores: `markdown-explorer-db` (`workspaces`), `markdown-explorer-browser-fonts` (`fonts`).
- `localStorage` keys: `markdown-explorer.user-virtual-workspaces.v1`, `markdown-explorer.virtual-ws-entries.v1.<id>`, `markdown-explorer.virtual-ws-content.v1.<id>`, `markdown-explorer.demo-workspace.v1`, `documentConversion`, `markdown-explorer-ui-state`, and `WEB_APP_STATE_STORAGE_KEY` (`markdown-explorer-web-state`, via `ui/src/platform/web.ts`).

## Known limitations and open questions

- `browser-git-history-host.ts` disables all Git history commands in browser runtimes (`unsupported-runtime`), and `browser-insights-host.ts` returns `unsupported` for `checkExternalLinks`.
- `#video-demo` currently renders a styled YouTube walkthrough placeholder (`data-youtube-video-id="coming-soon"`) until the recorded walkthrough video ID is published.
