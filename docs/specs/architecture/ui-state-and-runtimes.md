# UI State, Contexts, and Platform Runtimes

## Purpose and boundaries

Defines the client-side React UI architecture of Markdown Explorer: how the app bootstraps across four host runtimes (Electron desktop, Tauri desktop, VS Code webview, and Web), communicates with host processes via `PlatformBridge`, manages global application state in `AppStateProvider`, coordinates document/wiki navigation and Git history contexts, and orchestrates keyboard shortcuts, layout effects, modals, and lazy-loaded rendering libraries.

- **In scope**: `ui/src/main.tsx`, `ui/src/App.tsx`, `ui/src/AppView.tsx`, `ui/src/AppShell.tsx`, `ui/src/useAppLayoutEffects.ts`, `ui/src/platform/*`, `ui/src/contexts/*`, `ui/src/types/*`, `ui/src/constants/*`, `ui/src/hooks/*` (except `useDesktop*`), `ui/src/components/{Topbar,Tour,Modal,shared}/*`, `ui/src/lib/renderLibs.ts`, `ui/src/readingProgress/*`, `ui/src/utils/*`.
- **Out of scope**: Host runtime backends (`tauri/`, `electron/`, `vscode/`, `website-app/`), desktop tabs & settings UI (`feature.workspace-tabs-and-settings`), and Markdown/editor/insights/export engines.

## Observable behavior

- **Instant-paint bootstrap (`ui/src/main.tsx`)**: `detectBridge(win)` selects `createVsCodeBridge()` (`acquireVsCodeApi`), `createElectronBridge()` (`__TAURI__` / `__TAURI_INTERNALS__` adding `body.is-desktop` + `body.is-tauri`, or `electronAPI` adding `body.is-desktop` + `body.is-electron`), or `createWebBridge()` (`__webBus` adding `body.is-web`), then lazily renders `AppShell` and fades `.splash`. (Chromium extension `__chromeExtBus` / `platform/chrome.ts` was removed.)
- **First-run gates (`ui/src/App.tsx`, `ui/src/useAppLayoutEffects.ts`)**: Desktop runtimes gate on `TERMS_ACCEPTED_STORAGE_KEY === 'true'` (`TermsModal`), then `THEME_ONBOARDING_COMPLETE_STORAGE_KEY === 'true'` (`ThemeOnboardingModal`), then `USER_TOUR_COMPLETE_STORAGE_KEY` (`requestStartUserTour()`). Update checks (`useUpdateCheck`, `useUpdateNotificationState`) are disabled when `isWeb` / `runtime === 'web'`; `useFileDropOpen` accepts `{ isDesktop, isWeb }`.
- **Runtime-aware shell (`ui/src/AppView.tsx`, `ui/src/components/Topbar/*`)**: Renders `DesktopTabBar` when `(isDesktop || isWeb) && settings.desktopViewMode === 'tabs'`, otherwise `Topbar` when a workspace is active. Standalone Tauri defaults to `WelcomePage` until a non-tour workspace opens. `Topbar` and `DesktopTabBar` label the home menu action via `t.topbar.homeGetHelp || t.topbar.home` ("Home - Get help"). `WebDemoNavActions` renders on `isWebRuntime()` with mode switch (`?mode=web` vs `?mode=test`, labeled `'Markdown Explorer on Web'` / `'Mode Test'`) and a GitHub star badge (`★ {starsCount}` via `useGitHubStars()`).
- **Welcome, Modals & Menus (`WelcomePage.tsx`, `UserManualTab.tsx`, `WelcomeLaunchpad.tsx`, `ScopeViewModal.tsx`, `ScopeViewToc.tsx`, `MediaModal.tsx`, `TabContextMenu.tsx`, `SwitchWorkspaceModal.tsx`)**: `WelcomePage` defaults `activeTab` to `'manual'` (tabs ordered `manual`, `features`, `shortcuts`) and enables editor support in `web` runtime; `UserManualTab` uses updated AI help prompt copy (`"Get help to using Markdown Explorer by any AI"`); `WelcomeLaunchpad` and `SwitchWorkspaceModal` dispatch `createVirtualWorkspace` on `window.__webBus`; `ScopeViewModal` portals directly into `document.body` via `createPortal` at `--z-modal` (covering content below `--modal-region-top` across all themes), yields capture-phase `Escape` when `#mediaModal`, `#mdn-chart-modal`, `.mdn-align-dropdown`, or `.mdn-filter-dropdown` are open (closing `.mdn-filter-dropdown` first), widens `.scope-view__card` to `min(1600px, calc(100vw - 24px))` x `min(1120px, calc(100dvh - var(--modal-region-top) - 24px))` (`.scope-view__document` to `1120px`), strips inline `onclick` on `a[data-mdn-target]`, resolves relative scope links against `current.file.fsPath`, and adds a header TOC toggle button mounting `ScopeViewToc` (unfolding collapsed section parents via `expandParentSections`); `MediaModal` and `TabContextMenu` also portal directly into `document.body` via `createPortal` (`MediaModal` at `--z-modal-popover`) so image previews and tab menus stack above Scope View and `.toc-panel`.
- **State hydration, defaults & shortcuts (`ui/src/contexts/*`, `ui/src/hooks/*`)**: `AppState` defaults `themeStyle` to `'raw-grid'` (labeled `'Default'`; `'default'` is `'Explorer Classic'`), `settings.fileTabs` to `true` (`saved.fileTabs !== false`), `settings.bookmarksEnabled` to `true` (`saved.bookmarksEnabled !== false`), and `settings.historySidebarEnabled` to `false` (`saved.historySidebarEnabled === true`). `normalizeThemeStyle` coerces unknown/removed styles to `'raw-grid'` (while `reduceSettingsUiAction` preserves the `'glass'` test fixture). Desktop default keybindings map `Ctrl+Shift+E` to `openFiles`, `Ctrl+Alt+x` to `expandAll`, `Ctrl+E` to `editCurrentDocument`, and `Ctrl+Alt+E` to `plainEditCurrentDocument`; `normalizeKeybindingsForRuntime` applies `Ctrl+Alt+E` / `Ctrl+Alt+Shift+E` remapping on `vscode` and `web`, deletes `reloadWindow` on `web`, and gates `toggleWorkspaceInsights` via `supportsWorkspaceInsights(runtime)`. `useAppStateEffects` runs desktop typography sync for `'desktop' | 'tauri' | 'vscode' | 'web'`, hydrates `PersistedState` from `bridge.getState()`, posts `ready` with `readyId`, handles VS Code `restorePersistedState` -> `stateHydrated`, and filters workspace-scoped host messages via `acceptsWorkspaceHostMessage(msg)`.
- **Navigation, History & Lazy Libs**: `NavigationContext` maintains per-scope (`default`, `focus`, `tabId`) back/forward stacks and resolves `mdn-wiki-navigate` events; `HistoryProvider` manages `HistoryClient` and `FileHistoryModal`; `renderLibs.ts` provides retryable lazy loaders (`getHighlightJs`, `getMermaid`, `getChart`, `getKatex`); `readingProgressStore.ts` debounces (`500ms`) scroll/heading state for up to 100 recent files per workspace.

## Workflow

1. `main.tsx` runs `detectBridge()` -> `PlatformProvider` -> `Suspense(AppShell)`.
2. `AppStateProvider` hydrates persisted state and emits `ready`.
3. Host responds with `readyAck` (and `restorePersistedState` on VS Code).
4. `App` evaluates Terms -> Theme Onboarding -> User Tour gates.
5. User actions dispatch `AppAction` / post `WebviewMessage`; host responses update `AppState` via `appStateReducer`.

## Code map

- `ui/src/main.tsx`, `ui/src/AppShell.tsx`, `ui/src/App.tsx`, `ui/src/AppView.tsx`, `ui/src/useAppLayoutEffects.ts` — bootstrap, gates, shell layout, and resize/layout effects.

- `ui/src/contexts/{AppStateContext,appStateModel,appStateReducer,appStateConstants,useAppStateEffects}.ts(x)`, `ui/src/contexts/reducers/settingsUiReducer.ts` — global state, keybinding defaults, theme normalization, and host-message effects.

- `ui/src/types/{hostMessages,webviewMessages,content,files,settings}.ts`, `ui/src/themeTypes.ts`, `ui/src/constants/{storage,limits,urls}.ts` — message unions, domain types, storage keys, limits.

- `ui/src/lib/renderLibs.ts`, `ui/src/readingProgress/readingProgressStore.ts` — lazy library loaders and reading progress store.

## Interfaces and data

- `PlatformBridge`: `postMessage(msg)`, `onMessage(handler)`, `getState<T>()`, `setState<T>(state)`, `copyToClipboard(text)`.
- `AppRuntime`: `'desktop' | 'vscode' | 'web' | 'tauri'`.
- Storage keys (`ui/src/constants/storage.ts`): `markdown-explorer-ui-state`, `markdown-explorer-web-state`, `markdown-explorer-reading-progress-v1`, `markdown-explorer-terms-accepted`, `markdown-explorer-theme-onboarding-complete`, `markdown-explorer-user-tour-complete-v1`.

## Known limitations and open questions

- `isDesktop` in `ui/src/App.tsx` checks `typeof window.electronAPI !== 'undefined'` (true for both Electron and Tauri's shim), while `state.appRuntime === 'tauri'` arrives asynchronously in `readyAck`.
- `AppView(props: any)` in `ui/src/AppView.tsx` uses untyped `any` props rather than a strict interface.
